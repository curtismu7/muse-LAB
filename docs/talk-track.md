# Talk track: Muse (about 6 minutes)

Audience: an SE showing how a personal agent stays inside what it may do. Everything here is simulated.

1. **Set the scene (30 s).** "Muse is a personal agent. It acts for Sam, a finance lead. Every tool call goes through Agent Privilege."
2. **The 401 (60 s).** Before signing in, press *Call Agent Privilege with no token*. Open step 1: Agent Privilege answers 401 and its `WWW-Authenticate` header points at the resource metadata. Steps 2 and 3 say which authorization server to use and how. On a local run with live mode on, flip to *Real* and do the same against the real Agent Privilege.
3. **Sign in (30 s).** Click sign in. Point at the trace: PingOne starts the flow, a DaVinci step checks the risk, then the session is issued. Say that this is simulated.
4. **Allowed call (45 s).** Read the calendar. The call is allowed, and the decision log shows why.
5. **Coarse check (60 s).** Switch to staff (local build only) and try a payment. "The tool itself is closed to staff. The amount is never looked at."
6. **Fine check (60 s).** As Sam, send 120: allowed. Send 800: held. "Big payments wait for a person." Approve it, and point out that the approval is simulated CIBA.
7. **Muse-detect (90 s).** Press the burst button: seven calls in a row. The seventh is held. Then press the injected instruction button. "This one is blocked, not held. An instruction hidden in a draft never reaches a tool."
8. **Book a flight (2 min).** Open *Book a flight*. "Two rules, two owners, one gateway." Point at the two cards: *your* rule (no tickets bought by an AI agent over $500, your own setting) and the *airline's* rule (only premium members can book over $750). Say where the tier lives: a custom field on the PingOne user, `airlineMemberTier`, and PingOne Authorize reads it itself from the user, the gateway does not pass it. Premier Gold is premium; Premier Silver, anything else or no value is not. In Mock the three members are labelled as a Mock PingOne user that mimics that attribute. The *Member tier* card above the rows is the one control: Premier Gold, Premier Silver or No tier set. In Mock it changes the simulated member (a row sets it to its own tier and the card follows). Run the rows in order and read the banner each time: 1 agent $480 and 2 agent $500 pass (exactly $500 is not over). 3 agent $620 is stopped by your rule: "Authorize rule applied: booking stopped", the ledger says "Nothing booked." 4 agent $940 as a premium member: your rule still wins, premium does not help an agent. 5 Sam directly at $620 and 6 Sam directly at exactly $750 pass: your rule only limits agents. 7 Sam directly at $940 as a standard member: the airline rule. 8 same flight as a premium member: booked, one ledger row. 9 agent $940 as a standard member: both rules, both listed. 10 Sam directly at $940 with no tier set on the user: denied by the airline rule, because a missing tier is not premium. Open hop 3 to show the attributes the gateway gave Authorize (Amount, ActClientId, AgentSpendLimit; no tier), then hop 4: it names the member tier and its source, the PingOne user attribute `airlineMemberTier`. Press "try to lie": Muse says $100 for SH107 and the gateway still judges $940, because the fare comes from the catalogue. Booking calls are outside the burst check (velocity), so the burst demo in the step before does not hold any of the nine rows; say so if asked. Say plainly that Mock is a local stand-in and every hop says simulated. Then toggle to Real (owner-run: it needs the policy change imported and the gateway restarted): in Real the card writes the PingOne attribute `airlineMemberTier` on the demo users and reads it back, so press Premier Silver, say "PingOne now holds Premier Silver" (it is the read-back, not a hope), run rows 7 and 9, then press Premier Gold and run row 8. If the card is disabled it lists the settings it needs (owner-approved credential, see the README). Never claim the switch works in a real tenant until you have pressed it there once. Muse cannot see the tier in Real; hop 4 says `not reported to Muse` and names the PingOne attribute. A booking that passes both rules stops at the consent gate (HTTP 428), and Muse does not approve it.
8b. **Book from muse.ai (optional, owner-run, Real, 2 min).** Same two rules, driven from the other side. In muse.ai (connected to the Airline Connector) say: "List the flights I can book", then "Book SH106" ($620: denied; muse.ai reads out that an AI agent cannot buy a ticket over your limit, with the fare and the limit). "Book SH107" ($940) is where the airline rule shows up when the tier is Premier Silver: both rules are named. "Book SH101" ($180) passes both rules, so the gateway holds it for approval: muse.ai is told it is held and nothing was booked, and it cannot approve it. Say that plainly; do not promise a booked flight from muse.ai. Muse sends only the flight id, so there is no price for the agent to lie about. If every booking, even the cheap one, comes back as "you have not authorized this agent to act for you on bookings", the user's consent never reached Authorize: the connector passes it on only when the owner has set `MUSE_GATEWAY_INTERNAL_SECRET` (owner-approved exception, 2026-11-09), and the message says when it is not configured.
9. **Close (30 s).** "The decision order is detect, coarse, fine. The most restrictive answer wins. On-behalf-of token exchange is coming soon; the pattern diagram marks it, and this demo does not perform it."

Reset clears the visitor's session and decision log between runs. Presenter mode keeps the simulation banner on.
