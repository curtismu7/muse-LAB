# Personal Agent (Muse)

Personal-agent demo, tier Demo. A browser front end (Muse, the agent) signs in through PingOne, then calls tools through a Privilege-shaped gateway. By default (`MODE=mock`) everything is simulated and offline; `MODE=live` (with `ALLOW_LIVE=1`) is the owner's real build with their own PingOne and gateway. `/clients.html` shows Claude, ChatGPT, Codex and Muse as look-alike clients on the same back end.

## Run and test
- `npm install`
- `npm test` (server suite, node:test; `node --test server/test/*.test.js` also works)
- `npm run build` (web bundle)
- `npm start` (http://127.0.0.1:5100/); `node scripts/doctor.mjs` checks a running app.

## Book a flight (two Authorize rules)
- `server/src/fares.js`: the fare catalogue (`fares.json`, SH101-SH109), the two rules (`RULES`: names and codes match the Authorize policy: `mcp-airline-agent-spend-limit`, `mcp-airline-premium-only`), the Mock member records (`MEMBERS`: standard = Premier Silver, premium = Premier Gold, none = no `airlineMemberTier`; each mimics the PingOne user attribute, the agent limit lives there, default 500) and `evaluateBooking`. Strict "over": exactly 500 and 750 pass. Premium = `PREMIUM_TIERS` (explicit list, `Premier Gold` only; any other value, empty or missing is NOT premium). **The tier is the PingOne user attribute `airlineMemberTier` (owner decision 2026-11-09); in Real, PingOne Authorize reads it itself. The gateway does not look it up or send it, so Real usually shows `member tier not reported to Muse`; never invent a value. Mock labels its tier as a Mock PingOne user mimicking the attribute (`TIER_SOURCE_MOCK`); Real labels it `TIER_SOURCE_REAL`.**
- Mock: `gateway.js fineCheck('flights.book', args, {actor, member})` ignores `args.fare/amount/quoted/tier/limit`; `POST /api/member {member: standard|premium|none}` (and the card's `POST /api/booking/tier`) sets which Mock PingOne user the simulated Authorize reads (`/api/member` is refused in Real); `booking.js mockBooking` builds the five hops, all labelled simulated.
- Real: `POST /api/live/ask {scenario:'book', flightId, channel:'agent'|'user', quoted?}`; `booking.js classifyBooking` reads the gateway's answer (403 + `X-Gw-Audit-Trail` statements, 428 consent, 200 booked or not_booked, anything else an error). A direct-user token is kept in `ws.userToken` on the server only. Only tested against stubs.
- UI: `web/src/BookFlight.jsx`; diagram `booking-rules-flow` (also a tab on /diagram).
- Never call a real tenant or the real gateway from tests or agents; Real is owner-run.

## Member tier switch (owner-approved 2026-11-09)
- `server/src/tier.js` + `/api/booking/tier` (GET state, POST `{member: standard|premium|none}`) + `/api/booking/tier/read` (Real read-only) + the *Member tier* card in `web/src/BookFlight.jsx`. Mock: sets `ws.member` (the Mock PingOne user). Real: PATCHes `airlineMemberTier` on the `MUSE_TIER_USER_IDS` users (worker token by client credentials, Basic auth), reads each back, reports the real value. Tests: `server/test/tier.test.js` (stub PingOne only).
- **This is a DEVIATION from the rulebook, labelled owner-approved 2026-11-09:** a runtime PingOne credential (`MUSE_TIER_WORKER_CLIENT_ID`, `MUSE_TIER_WORKER_CLIENT_SECRET`, `MUSE_TIER_USER_IDS`, `MUSE_TIER_ENV_ID`, `MUSE_TIER_REGION`; names only here) for this feature only. Keep it narrow: one attribute, three values (Gold, Silver, clear), allow-listed ids from env never from a request, hosts `auth.pingone.<region>` / `api.pingone.<region>` only, secret and token never returned, logged, scrubbed from errors, off on a hosted build, Real only. Do not widen it, do not reuse `provisioning.json`, never read or print `.env`.
- Agents never call a real tenant for this: test only against the stub in `tier.test.js`. Clearing with `null` and the worker app's required role are UNVERIFIED against a real tenant.

## Rules that bite
- Mock mode contacts nothing: the netguard (`server/src/netguard.js`) refuses every non-loopback outbound call and counts them (`GET /api/netguard`; the doctor and a test assert zero attempts). In live mode it only counts origins.
- Branding is data: `server/src/customer.config.json` (brandName, agentName, tagline, default vertical); `MUSE_CUSTOMER_CONFIG` points at another file. Bad values fall back to the defaults.
- Stories are data: `server/src/stories.json`, three vertical packs (airline, bank, hotel) with `{{cast.x}}` tokens and the runtime tokens `{{points}}` and `{{tier}}`. An undefined token fails the load and the tests. Live sign-in runs the airline back end only.
- Each browser gets its own workspace; `workspaceId` (a hash, never the cookie) labels it. Nothing is written to disk.
- Loopback bind unless `MUSE_HOSTED=1`. Host check and same-origin writes on every API call.
- Persona picker only with `IDP=mock` and `ALLOW_MOCK_SIGNIN=1`, never hosted.
- No SE host names, tenant or client ids in shipped files (a test pins it). Real settings live in `.env` (see `.env.example`) or the owner's Secret, never in the repo.
- Live sign-in is pi.flow, not a redirect: the page opens the Sign in dialog (`web/src/SignInModal.jsx`), which runs PingOne's DaVinci flow with Ping's DaVinci client SDK (`@forgerock/davinci-client`, plus `@forgerock/protect` for the Protect screen). `POST /api/live/signin` with `piflow: true` returns the SDK's config (state, challenge, hint; never the verifier) and `POST /api/live/signin/complete` swaps the code on the server. The PingOne app must list the page's origin in its CORS settings (without it the browser blocks the flow). The connector's `/connector/authorize` (real assistants and the simulated ones from `/api/sim/start` and `clients.html`) sends the browser to Personal Agent's own `/connector/signin` page, which runs the same dialog (`/connector/signin/config`, `/connector/signin/complete`); the only redirect left is back to the assistant's own redirect address. Each PingOne app a sign-in uses (the base app and the per-assistant apps) needs the page's origin in its CORS settings and `<public url>/connector/callback` in its redirect URIs. Without a PingOne app (`MUSE_P1_ENV_ID`, `MUSE_P1_CLIENT_ID`) Real mode refuses to register or sign in (409); there is no redirect fallback and no dynamic client registration against the gateway's own authorization server.
